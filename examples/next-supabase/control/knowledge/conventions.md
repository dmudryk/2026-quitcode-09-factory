# Домовленості проєкту (для будівельника)

- Next.js App Router + TypeScript + Supabase. Логіка домену — у `src/lib/**` (чисті функції з unit-тестами);
  сторінки — у `src/app/**`; серверні дії — у `src/app/**/actions.ts`. Псевдонім імпорту `@/` = `src/`.
- Тести захищені: ніколи не змінюйте `tests/**` і `*.test.ts(x)`. Червоні тести критеріїв мають стати зеленими через зміну
  коду продукту.
- Тести запускайте лише так: `node scripts/factory-tap.mjs` (TAP, один рядок на ID критерію). Не використовуйте npm/npx,
  конвеєри (`|`), перенаправлення (`>`) і ланцюжки (`&&`): політика фабрики їх забороняє.
- Зміни бази — лише НОВИМ файлом міграції `supabase/migrations/<YYYYMMDDHHMMSS>_<назва>.sql` з пізнішою датою, ніж
  у наявних. Наявні міграції не редагуйте. У новій таблиці — RLS, політики й grants; перевірки доступу дублюйте на сервері.
- Тексти повідомлень в інтерфейсі — дослівно з вимог PM; не перефразовуйте.
- Мінімальна зміна: найменший diff, з яким правило виконується загалом, а не лише для прикладів у тестах.

Відредагуйте цей файл під свій проєкт: ключове з `AGENTS.md`/`CLAUDE.md`. Фабрика запускає Claude Code з
`--setting-sources ""`, тож правила й навички репозиторію будівельник, імовірно, не бачить — бачить цю теку `knowledge/`.
