# Приклад control для близнюка Next.js + Supabase (курсова редакція WS9)

Скопіюйте цю теку ПОЗА репозиторій продукту (наприклад `C:/pf/control`) — це ваш «пульт» фабрики: конфігурація, політика,
правила, задачі, приховані сценарії. Люди пишуть його; фабрика лише читає. Повний порядок дій — `docs/uk/README.md`.

| Файл | Що в ньому |
|---|---|
| `factory.json` | модель будівельника й рев'юера (Sonnet), бюджети (`runUsd 8`, `dailyUsd 30`, 3 спроби), ворота, рівні автономії, `delivery` (push, PR, автозлиття) |
| `policy.json` | AI-політика: дозволені моделі й інструменти, які класи змін можна випускати без людини, межа даних (`**/.env*` заборонено) |
| `rules.json` | правила супроводжуваності: розмір файлів, дублювання, напрям залежностей для `src/**/*.ts(x)` |
| `knowledge/conventions.md` | домовленості проєкту для будівельника — відредагуйте під свій репозиторій |
| `evaluators/vitest-holdout.mjs` | запускає приховані Vitest/PGlite-сценарії на копії кандидата |
| `holdouts/example.json` | шаблон набору прихованих сценаріїв — перейменуйте, напишіть свої, запечатайте |
| `tasks/` | задачі, згенеровані `tools/ac-to-task.mjs` |

Профіль `next-vitest` вбудований у фабрику (`profiles/next-vitest.json`); щоб змінити його, покладіть свою копію в
`profiles/next-vitest.json` цієї теки — локальний профіль має пріоритет.

## Рівні автономії: чому тут усе `auto`

У цьому прикладі **кожен клас змін — `auto`, міграції теж**, а `policy.unattendedClasses` містить `docs`, `code`,
`migration` і `default` (файли поза класами). Тобто після всіх воріт фабрика випускає зміну без людини, а `factory deliver`
вмикає автозлиття PR. Це рішення автора курсу для **близнюка** — окремого репозиторію з власним Supabase і Vercel, де
автозлиття й `db-deploy` не можуть зачепити прод основного проєкту.

Типові налаштування upstream суворіші, і для справжнього проду беріть їх:

- документація — `auto`; код — `one-human` (випуск затверджує одна людина, і не та, що замовила зміну);
  міграції — `two-humans`; файли поза класами — `one-human`;
- AI-політика дозволяє без людини лише `docs`; навіть якщо клас позначено `auto`, але його немає в `unattendedClasses`,
  фабрика підніме його до `one-human`;
- інцидент (`factory incident`) знижує клас на рівень, доки він не заробить довіру чистими випусками (`promoteAfter`).

Без людини між воротами й продом сітка безпеки — обов'язкові перевірки CI на гілці (ruleset), UAT після розгортання
(`factory uat`) і інцидент → пониження рівня. Див. `docs/uk/limits.md`.
